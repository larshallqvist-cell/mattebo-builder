# Edge function rules

- The student Bråklabbet (owner-authorized copy of the generic lab) lives only in `supabase/functions/braklabbet-content/source/`, bundled by `scripts/build-braklabbet-content.mjs` into `content.ts` and served only after server-side checks in `access.ts`; `/braklabbet?lab=1` (admin only) renders it in a sandboxed `srcDoc` iframe without `allow-same-origin` or tokens, so it is never a public asset. Mission progress cannot live inside that sandbox; the iframe reports completions over `postMessage` and `src/pages/Braklabbet.tsx` persists them in `public.braklabbet_progress` (RLS: own rows only), never by passing tokens into the iframe.
- Fraction training keeps its exercise/grading source in the protected lab, with a generated `_shared/braklabbet-exercises.js` copy for deployment; common access decisions live in `_shared/braklabbet-access.ts`. Only the server records attempts, computes correctness and atomic attempt numbers, and deduplicates retries by request ID. Students read own attempts and existing admins read all through RLS; the parent relays answers and minimal results without iframe tokens. Training RLS checks the protected roles table directly (`public.user_roles`); `has_role` was later made executable by client roles in migration 0014, so keep the direct check.
- `exercise-task` imports `_shared/exercises/` copies of `src/lib/procent.ts` and `src/lib/ekvationer.ts` (run `node scripts/sync-exercise-libs.mjs`; `tests/exerciseLibsCopy.test.ts` fails on drift), so server grading always matches the page. Tasks live in server-only public.exercise_tasks; the Procent streak is computed from saved answers.
- Google Calendar is the source of truth for lesson text: Admin saves patch the event first and copy to the sheet best-effort, the Apps Script (docs/) only pulls calendar → sheet automatically, and pages pick text via src/lib/lessonSource.ts (tested) so a Mattebo copy shows only while newer than the event's LAST-MODIFIED; this stops the sheet and calendar overwriting each other.
- AI student analysis (`student-analysis` function, Elevkort): admin-only server check; the server aggregates per-game correct rates/error kinds, self-assessment and surveys without names, plus exam rows from admin-linked sheets (`public.exam_sheets`, parsed by `_shared/examSheet.ts`, tested; matched to the student by full name server-side and cached in `google_sheet_cache`) and optional pasted text, so raw rows and identities never reach the model.
