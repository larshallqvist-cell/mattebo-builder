# Project architecture rules

Subdirectories have their own `AGENTS.md` (e.g. `src/lib/`, `supabase/functions/`); read it before changing files there. Student Bråklabbet and fraction-training rules live in `supabase/functions/AGENTS.md`.

- Student activity is mounted once inside the router for approved non-admin users; foreground interaction estimates pause after 60 seconds idle and start a new visit after 30 minutes away. Only allowlisted page names, visit IDs and seconds are recorded through an authenticated, server-timestamped RPC; no input contents or external browsing are captured. A cross-tab foreground lease prevents simultaneous time counting. Admin-only directory RPC exposes only student names and last sign-in; timelines reuse existing exercise and resource records under admin SELECT policies.

- Cache quota-limited Google Sheets reads in the server-only `google_sheet_cache` table; frontend clients must never access this cache or connector credentials.
- The private teacher Bråklabbet is a separate owner-only app; reach it only as an external admin link via `PRIVATE_BRAKLABBET_URL`, never embed that URL, so its own access rules stay in charge.
- Grade-page navigation stays in document flow with a wrapping second row for lesson controls; this reserves its actual height and prevents overlap at narrow widths or enlarged text sizes.
- Tabelltestet (`/tabelltestet`) is a plain React page; pass rules and question generation live in `src/lib/tabelltest.ts` with bun tests in `tests/tabelltest.test.ts`. Results go to `public.tabelltest_results` (RLS: own rows, admin reads all). Continuous speech recognition calls the latest answer callback through a ref so it never grades against a previous question; `src/lib/tabelltestVoice.ts` accepts stable interim numbers and deduplicates by utterance index so delayed final events never answer the next question. `tests/tabelltest-voice.e2e.py` covers one full continuous session without storing test results.
- Algebra (/algebra) is a plain client-side React page; generation and answer checking live in src/lib/algebra.ts with exact fractions, tested in tests/algebra.test.ts. Each graded answer is logged to public.algebra_attempts (RLS: own insert by approved users, admin reads all); stats/level-status rules live in src/lib/algebraStats.ts, tested in tests/algebraStats.test.ts. Next-level encouragement (src/lib/algebraEncouragement.ts, tested) is tracked locally per mode/level from first-try timed exercises, so it never changes saved statistics or moves students automatically.
- Grade pages use one responsive layout built from `CollapsibleSection`: a chapter-focused main column (header holds the chapter title (opens the chapter picker) and sub-chapter chips, body is Resurser → Övningar och spel, ~70% at ≥1024px; from 1280px Resurser and the games sit side by side in it) and one notice-board section (post-it, läxa, planering, Mat-t-e; calculator and lunch are header buttons) that is a sticky right column on wide screens and a folded card on mobile; never duplicate panels per breakpoint so data hooks and widgets mount once. Sub-chapters live in `public.chapter_sections` (approved read, admin write) with parsing rules in `src/lib/chapterSections.ts`, tested in `tests/chapterSections.test.ts`.
- No app-shell service worker: public/sw.js is a kill-switch that clears old Workbox caches and unregisters, and src/pwa.ts unregisters leftovers; the manifest is static so the app stays installable while users always load the latest published version.
- Procent (/procent) is a drill page; generation, tiers and streaks live in src/lib/procent.ts (tested in tests/procent.test.ts), the clickable triangle in src/components/procent/. Every answer goes to public.procent_attempts (mode `mangd`, level = tier, streak after answer; RLS own insert/read, admin reads all), summarized with the shared algebraStats rules.
- Exercise pages (Procent, Algebra, Tabelltestet) share `src/components/exercise/` (ExerciseShell, ExerciseParts, GuideRobot) and the `.exercise-light` CSS scope, which only remaps theme variables; keep page logic in each page and styling in the shared shell so all exercise pages stay consistent.
- Ekvationspusslet (/ekvationer) follows the Procent pattern: generation, left-to-right error detection and step explanations live in src/lib/ekvationer.ts (tested in tests/ekvationer.test.ts), lines stay in logical order (line i introduces figure i) while Puzzle.order shuffles the shown order from level 2, so explanations follow the logic and cite the shown row numbers. Attempts go to public.ekvation_attempts (RLS like procent_attempts) with puzzle_id, error kind and capped seconds per answer; progression, mastery and the assessment summary live only in src/lib/ekvationStats.ts (tested in tests/ekvationStats.test.ts) so the student view, Admin and Elevkort always agree. Figures have no theme picker: src/lib/ekvationer.ts pickFigures mixes celebrities into emoji puzzles by level (tested shares), and the deprecated theme column defaults for new rows. Profile portraits come only from teacher-uploaded cut-out photos served as CDN assets (src/assets/profiles/); a profile with a photo shows no name label or hover title, profiles without one keep name + icon.
- Exercise and game routes (/braklabbet, /tabelltestet, /algebra, /procent, /ekvationer) are wrapped in `LoginGate` in `src/App.tsx`, and the start page header shows only sign-in; so games are reachable only by approved signed-in users, even via a direct address.
- Self-assessment (src/lib/selfAssessment.ts, tested): default questions live in code, teacher edits in public.self_assessment_questions override per sub-chapter; responses store the question texts with ratings on the current SCALE values only (values outside it, from older scales, are ignored in summaries and prefill) so edited questions or scales never mismatch old answers.
